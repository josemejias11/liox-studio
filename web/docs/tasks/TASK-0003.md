# TASK-0003: Frontend — lesson view tracking, adaptive weakTopics wiring, analytics dashboard panel

## Goal
Fire a lesson-view event on every navigation, merge population-level weak topics from `/api/analytics/weak-topics` into quiz generation, and surface a "Lesson Engagement" panel on the analytics dashboard.

## Context
The AI quiz generator already accepts `weakTopics: string[]` to steer RAG question generation. `MotoViewer.buildWeakTopics()` (line 150) currently only looks at the **current session's unvisited hotspots** — a purely local signal. TASK-0002 adds the server-side analytics endpoint; this task wires the frontend to produce richer, population-aware weak topics and to display lesson engagement data on the instructor dashboard. Additionally, lesson views are currently only recorded when a hotspot is tapped inside a lesson; this task adds a view event on every lesson navigation so all lesson types are tracked.

## Affected Area
- Layer: frontend
- Agent role: web-engineer

### Patterns in use
- `MotoViewer` is a `'use client'` component. Async fetch calls inside it must use `useEffect` or event handlers — not top-level `await`.
- `useLessonProgress` uses `useSWR` for GET and fires-and-forgets POST via `mutate`. Follow the same pattern for `markLessonViewed`.
- Progress is gated by `persistSession` (consent check). If `persistSession` is false, fire the POST only to increment in-memory state, not to the server.
- `getAnalyticsData()` is a server function called from the RSC analytics page — it can use `prisma` directly. Do not import `getLessonEngagement` into client components.
- `analytics/page.tsx` is an async RSC (no `'use client'` directive). Add the new panel as a server-rendered section.

### Known constraints
- **Do not add `courseId` to the `LessonProgress` composite PK** (`@@id([sessionId, lessonId])`). The schema change is on TASK-0002's side; here you only need to pass `courseId` in the POST body.
- The lesson-view event should fire **once per lesson navigation** — use a `useEffect` that depends on `lessonKey` (the current lesson's `_key`). Guard with `if (!lessonKey) return` to avoid firing on cover/quiz/disclaimer phases.
- `buildWeakTopics` currently runs synchronously just before rendering `<QuizLesson>`. Replace it with a `useEffect` + `useState` that fetches `/api/analytics/weak-topics` when the quiz phase is about to render (watch for `phase.phase === 'quiz'` or `currentLesson?.lessonType === 'quiz'`).
- The `weakTopics` state should merge both sources: session-local unvisited hotspot topics (existing logic) PLUS topics from the endpoint. Deduplicate. Cap at 15.
- The analytics dashboard lesson engagement panel should show lessons sorted ascending by viewCount (fewest first), with a simple horizontal bar and a `courseId` filter note ("Showing data for the current course"). Since the dashboard page is not scoped to a courseId (it's global), show aggregate counts across all courses but label the bars with their lessonId short-hash for now.

## Requirements

1. **`markLessonViewed`**: Add a new function to `useLessonProgress` that POSTs `{ type: 'lesson', sessionId, lessonId, courseId }` without `visitedHotspots` or `completed`. This registers a view. Fire it only when `persist === true`.
2. **Lesson view event in MotoViewer**: Add a `useEffect` in `MotoViewer.tsx` that calls `markLessonViewed(lessonKey, course._id)` whenever `lessonKey` changes and is non-empty (i.e., when the user navigates to a new lesson in the `chapter` phase).
3. **Adaptive `weakTopics`**: Replace the synchronous `buildWeakTopics()` with a `useEffect` + `useState<string[]>` that:
   - Seeds the state immediately with the session-local signal (existing hotspot logic, capped at 10).
   - When `phase.phase === 'quiz'` OR `currentLesson?.lessonType === 'quiz'` becomes true, fires `POST /api/analytics/weak-topics` with `{ courseId: course._id, lessons: structure.lessonSections.map(s => ({ id: s._key, headline: s.headline, topics: [...(s.hotspots ?? []).map(h => h.topic || h.label), s.headline] })) }`.

   - Updates the state; the already-rendered `<QuizLesson weakTopics={weakTopics}>` will re-render with the richer signal.
4. **`getAnalyticsData` update**: In `src/services/analytics.service.ts`, add a call to `getLessonEngagement("")` (empty string = all courses, no filter) inside the existing `Promise.all`. Add `lessonEngagement: Array<{ lessonId: string; viewCount: number }>` to the return type.
5. **Dashboard panel**: In `src/app/analytics/page.tsx`, destructure `lessonEngagement` from `getAnalyticsData()` and render a new `<section>` below the charts row titled "Lesson Engagement (least viewed first)". Show a bar chart row per lesson, matching the style of the existing "Top Features Explored" section. If `lessonEngagement` is empty, show an italic "No lesson data yet." message.
