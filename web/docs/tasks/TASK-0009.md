earns its own file. This is a pure mechanical extraction — a reviewer flagged the

### Patterns in use
- Components are one-per-file, PascalCase filename matching the component
  (`ChapterIntro.tsx`, `CourseQuiz.tsx`, etc.) — `SanityQuizPlayer.tsx` fits this.
- `'use client';` is the first line of interactive components.
- Imports are grouped: React/next/third-party, then `@/` absolute aliases.
  `QuizLesson.tsx` mixes some relative (`@/components/...`) and `@/lib/...` paths —
  preserve the existing style.
- `SanityQuizPlayer` is currently **not exported** (internal to the file). When
  moved it must be exported from the new file and imported back into
  `QuizLesson.tsx`.

### Known constraints
- **No behavior change.** This is an extraction only — do not rename props, alter
  JSX, touch the grading fetch calls, or change the state machine.
- **`QuizLesson`'s public export must remain unchanged** so `MotoViewer.tsx`'s
  `import('./QuizLesson').then((m) => m.QuizLesson)` keeps resolving. Do not edit
  `MotoViewer.tsx`.
- After the move, **prune imports in both files** so neither has unused imports
  (eslint will flag them). `QuizLesson.tsx` will likely only still need
  `CourseQuiz`, the `SanityQuizDoc` type, and the new `SanityQuizPlayer` import;
  everything else (`Image`, `motion`, `confetti`, most `lucide-react` icons, the
