# TASK-0005: Retheme CourseQuiz to use design-system tokens

## Goal
Replace all hardcoded `slate-` and `emerald-` Tailwind color classes in `CourseQuiz.tsx` with the project's design-system tokens (`bg-background`, `text-foreground`, `text-accent`, `border-border`, etc.) so the component respects dark/light mode and matches the rest of the course player.

## Context
`CourseQuiz.tsx` was created on Jun 11 ("vercel 6") as the AI-quiz widget used for in-lesson quizzes. It was built with a glassmorphic light-card aesthetic (`bg-white/70`, `dark:bg-slate-900/70`, `text-emerald-600`, `border-slate-200/50`, etc.) that predates the project's design-system token approach. Every other component in the player — `SanityQuizPlayer`, `DisclaimerPage`, `ContentLesson`, etc. — uses `bg-background`, `text-foreground`, `text-accent`, and `border-border`. `CourseQuiz` stands out visually in dark mode and will not adapt to any theme change. No layout or logic changes are needed — only colour tokens.

### Patterns in use
- Every `dark:` paired class must be removed — the tokens handle dark mode via CSS variables.
- The card outer border: `border-border/20` is the standard subtle card border used elsewhere (e.g., `DisclaimerPage`, `NavMap`).
- Correct answer state in `SanityQuizPlayer` uses `border-accent/65 bg-accent/12`; use the same here for consistency.
- Wrong answer state uses `border-border/65 bg-muted/12` in `SanityQuizPlayer`; match it.
- `backdrop-blur-xl` and `rounded-2xl` can stay — they're structural, not colour.
- `shadow-xl` on the outer card can stay.

### Known constraints
- No logic changes. Only Tailwind class substitutions.
- Do not change props, state, or event handler logic.
- Do not add or remove JSX elements.
- After substitution, the component must have zero `dark:` prefixed classes remaining (the token system handles theming via CSS variables).
- No TypeScript errors (`npm run typecheck`).

## Requirements
