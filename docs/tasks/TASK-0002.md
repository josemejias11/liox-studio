**Status:** todo

## Goal
The `scrollStory` lesson type renders its sticky hero/chapter background images (and the per-chapter crossfade) visibly behind the chapter cards — done = images are visible on screen.

## Context
The scroll-story pipeline is data-complete: the GROQ projection emits `scrollChapters[].image.asset.url` and the hero `media.asset.url`, the Zod contract mirrors them, `next/image` is configured for `cdn.sanity.io` (custom loader + remotePattern), and the CSP `img-src` allows the Sanity CDN. ### Root cause (verified, copied from source)
`ScrollStoryLesson.tsx` builds this DOM:

```tsx
// (A) scroll container
<div ref={scrollContainerRef} className="relative w-full h-full overflow-y-scroll">
  {/* (B) tall track — paints an OPAQUE background */}
  <div style={{ height: containerHeight }} className="relative w-full bg-background">

    {/* (C) sticky hero image — NEGATIVE z-index */}
    <div className="sticky top-0 h-screen w-full overflow-hidden flex items-center justify-center -z-10">
      {/* crossfadeImage → <Image fill ... className="object-contain" /> */}
    </div>

    {/* (D) chapters foreground */}
    <div className="relative z-10 w-full flex flex-col md:items-end pointer-events-none">
      ...
    </div>
  </div>
</div>
```

(B) is `position: relative` with `z-index: auto`, so it does **not** create a stacking context; its `bg-background` is opaque. (C) is `position: sticky` with `z-index: -10`, which paints in the negative-z layer *behind* (B)'s box background. Result: the hero/chapter images are painted, then covered by (B)'s opaque background. (D) at `z-10` stays on top, so only the chapter cards are visible — matching the reported symptom.

The per-chapter `crossfadeImage` (the `<Image fill>` inside `absolute inset-0`) and the `activeImageUrl` fallback walk are correct and must be preserved.

### Patterns in use
- One file per lesson type under `src/player/lesson-types/`; registered in `registry.ts` (no registry change needed — this is a CSS fix inside an existing component).
- Background images are layered as `absolute inset-0` at the base layer and foreground UI at positive z (see `ProductStage.tsx:234` background vs `z-20`/`z-30` overlays). The base background does **not** use a negative z-index.
- `next/image` with `fill` requires a positioned ancestor with real dimensions; the existing `absolute inset-0` wrapper around `<Image>` satisfies this — keep it.
- Tailwind utility classes only; no inline styles except the existing dynamic `containerHeight`.
- No comments unless the WHY is non-obvious.
