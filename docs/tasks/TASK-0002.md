# TASK-0002: Add `unsafe-eval` to CSP script-src in development mode

## Goal
Eliminate the `eval() is not supported` console error in development by adding `'unsafe-eval'` to the `script-src` CSP directive only when `NODE_ENV !== 'production'`.

## Context
React 19 in development mode uses `eval()` for debugging features (callstack reconstruction across environments). The current `MAIN_CSP` in `next.config.ts` sets `script-src 'self' 'unsafe-inline'` with no `'unsafe-eval'`, which blocks this and produces a console error on every page load in dev. React explicitly states it never uses `eval()` in production, so the directive must only be added for development builds — production CSP must remain strict.

## Affected Area
- Layer: infra / frontend (Next.js security headers)
- Agent role: `web-engineer`

## Codebase Context

### Entry-point files

| File | Why it matters |
|------|----------------|
| `web/next.config.ts` | Sole location of CSP headers — `MAIN_CSP` and `STUDIO_CSP` are defined and wired into `async headers()` here |

### Relevant symbols

```ts
// web/next.config.ts — current MAIN_CSP (lines 25–39)
const MAIN_CSP = [
  "default-src 'self'",
  "script-src 'self' 'unsafe-inline'",   // ← missing 'unsafe-eval' for dev
  "style-src 'self' 'unsafe-inline'",
  `img-src ${SHARED_IMG_SRC}`,
  "font-src 'self'",
  "connect-src 'self'",
  "worker-src 'self'",
  "frame-src 'none'",
  "frame-ancestors 'none'",
  "base-uri 'self'",
  "form-action 'self'",
]
  .join('; ')
  .trim();

// web/next.config.ts — STUDIO_CSP already has 'unsafe-eval' (lines 50–64)
// script-src 'self' 'unsafe-inline' 'unsafe-eval'   ← reference for correct value
```

### Patterns in use
- CSP strings are assembled as arrays of directive strings then `.join('; ').trim()`.
- `STUDIO_CSP` already includes `'unsafe-eval'` in `script-src` — follow the same pattern.
- `next.config.ts` is a plain TypeScript module; `process.env.NODE_ENV` is available at config evaluation time.
- Do not split `MAIN_CSP` into multiple variables unless necessary — keep the diff minimal.

### Known constraints
- **Do not add `'unsafe-eval'` to production CSP.** React does not need it in production and removing it from prod would be a security regression.
- Do not touch `STUDIO_CSP` — it already has `'unsafe-eval'` and is correct.
- Do not touch `COMMON_HEADERS` or the `headers()` wiring — only the `script-src` line inside `MAIN_CSP` needs to change.
- No new dependencies permitted.

## Requirements

1. In `web/next.config.ts`, conditionally append `'unsafe-eval'` to the `script-src` directive of `MAIN_CSP` when `process.env.NODE_ENV !== 'production'`.
2. The production CSP (`NODE_ENV === 'production'`) must remain unchanged: `script-src 'self' 'unsafe-inline'` with no `'unsafe-eval'`.
3. The dev-mode `eval()` console error must no longer appear after the fix.
4. No TypeScript errors (`npm run typecheck` passes).

## Implementation hint

Replace the `script-src` line inside `MAIN_CSP` with a conditional:

```ts
const isDev = process.env.NODE_ENV !== 'production';

const MAIN_CSP = [
  "default-src 'self'",
  `script-src 'self' 'unsafe-inline'${isDev ? " 'unsafe-eval'" : ''}`,
  // ... rest unchanged
```
