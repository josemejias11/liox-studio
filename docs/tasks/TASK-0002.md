# TASK-0002: Migrate analytics guard from deprecated `middleware.ts` to `proxy.ts`

## Goal
Rename `src/middleware.ts` → `src/proxy.ts` and its export from `middleware` → `proxy` so the analytics-route guard is active and no longer triggers the Next.js 16 deprecation warning.

## Context
Next.js 16 deprecated the `middleware` file/export convention in favor of `proxy`. The project runs `next@16.2.9`. A previous session created `src/middleware.ts` with `export function middleware(...)` as a security fix (the original `proxy.ts` had an incorrectly named export and was dead code). That fix is correct in behaviour but now causes a runtime deprecation warning because Next.js 16 expects `proxy.ts` + `export function proxy`. The codemod `npx @next/codemod@latest middleware-to-proxy .` performs this rename automatically but must be followed by a typecheck. The `NextRequest`/`NextResponse` imports and the `config.matcher` shape are unchanged.

## Affected Area

- Agent role: web-engineer

```ts
import { NextRequest, NextResponse } from 'next/server';

export function proxy(req: NextRequest): NextResponse { ... }  // only this line changes

export const config = {   // identical — matcher is unchanged
  matcher: [
    '/analytics',
    '/analytics/((?!login).*)',
  ],
};
```

The full body of `proxy` / `middleware` is identical; only the function name changes.

### Patterns in use
- The comment block at the top of the file documents the guard's purpose — keep it, just update the function name reference if mentioned.
- No other file imports from `middleware.ts` — Next.js picks it up by convention, so no import updates are needed elsewhere.
- `npm run typecheck` (from `web/`) is the acceptance gate after the change.

### Known constraints
- Do **not** create a second guard file — only `proxy.ts` should exist in `src/` after this task. Delete `middleware.ts` once `proxy.ts` is written.
- Do **not** change the `config.matcher` — the pattern was deliberately crafted to exclude `/analytics/login` and avoid an infinite redirect loop.
- The function body (cookie check, redirect logic, `fail-closed` behaviour when `ANALYTICS_PASSWORD` is unset) must be preserved exactly.
- `ProxyConfig` is the Next.js 16 type alias for the old `MiddlewareConfig` — if typing the `config` export explicitly, use `ProxyConfig` from `'next/server'`. In practice the inline `export const config = { matcher: [...] }` works without an explicit type annotation.

## Requirements
1. `src/middleware.ts` is deleted.
2. `src/proxy.ts` exists with `export function proxy(req: NextRequest): NextResponse` and the identical guard body.
3. `export const config` with the same `matcher` array is present in `proxy.ts`.
4. `npm run typecheck` exits 0 with no new errors.
5. The Next.js deprecation warning `The "middleware" file convention is deprecated` no longer appears on `npm run dev`.
