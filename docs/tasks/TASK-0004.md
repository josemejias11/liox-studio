# TASK-0004: Rename middleware.ts → proxy.ts (Next.js 16 convention)

## Goal
Rename `web/src/middleware.ts` to `web/src/proxy.ts` so Next.js 16 stops emitting the deprecation warning on every dev-server boot.

## Context
Next.js 16 deprecated the `middleware` filename convention in favour of `proxy`. Every `npm run dev` and `npm run build` currently emits: `⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.` This is purely a file rename — no logic changes. Next.js automatically discovers the file by name; nothing imports it explicitly.

## Affected Area
- Layer: infra / frontend (Next.js route convention)
- Agent role: `web-engineer`

### Patterns in use
- Next.js discovers `proxy.ts` (and `middleware.ts`) by convention from `src/` — no import path to update anywhere in the codebase.
- The exported function name (`middleware`) and `config` export stay the same — only the filename changes.
- Do not change the matcher, logic, or any imports inside the file.

### Known constraints
- No other file imports `middleware.ts` — confirmed by grep. The rename is safe.
- Do not rename the exported `function middleware` — Next.js still expects that export name regardless of filename.
- `npm run typecheck` must pass after the rename.

## Requirements

1. Delete (or rename) `web/src/middleware.ts` → `web/src/proxy.ts` with identical contents.
2. Confirm no other file in `web/src/` imports from `'./middleware'`, `'../middleware'`, or any relative path pointing to the old file.
3. Start the dev server and confirm the deprecation warning is gone from the boot log.
4. `npm run typecheck` passes.
