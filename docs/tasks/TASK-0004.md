# TASK-0004: Add dotenv support to parser-service

**Status:** todo
**Depends:** TASK-0003

## Goal
`python main.py` (and `run.sh`) work out of the box after cloning — no manual `export PARSER_SERVICE_TOKEN` required.

## Context
`parser-service/main.py` raises `RuntimeError` at startup if `PARSER_SERVICE_TOKEN` is absent from the environment. The token is defined in `web/.env.local`, but the parser service never reads that file — it has no dotenv loader and no `.env` of its own. Developers must remember to `export PARSER_SERVICE_TOKEN=...` in every new shell before starting the service, which is the failure mode that caused the "couldn't reach the assistant" error (the service never started cleanly after the port-800 incident in TASK-0003). Adding `python-dotenv` with a `parser-service/.env` file closes the gap.

### Patterns in use
- All tunables use `os.environ.get("VAR", "default")` — keep this pattern; dotenv just pre-populates `os.environ` before those reads.
- `python-dotenv`'s `load_dotenv(override=False)` is the right call: shell exports win over the file, so `PARSER_SERVICE_TOKEN=x python main.py` still works.
- The `.env` file must be gitignored (it contains a shared secret).
- `web/.env.local` is already gitignored; follow the same pattern for `parser-service/.env`.

### Known constraints
- Do not change the token-validation logic in the `lifespan` handler — it's correct as-is.
- Do not change any public API surface (endpoints, request/response shapes).
- `python-dotenv` must be pinned to a concrete version in `requirements.txt` (check PyPI for the latest stable, currently `1.1.0`).
- `load_dotenv()` must be called **before** the module-level `os.environ.get(...)` calls (lines 46-74), i.e., immediately after the stdlib imports and before the third-party imports block.
- `.gitignore` at the repo root already ignores `*.env` and `.env*` — confirm before adding a new ignore rule.

## Requirements

1. **`python-dotenv` dependency** — add `python-dotenv==1.1.0` to `parser-service/requirements.txt`.

2. **Load dotenv at module start** — in `main.py`, add:
   ```python
   from dotenv import load_dotenv
   load_dotenv(override=False)   # shell env wins; .env is the fallback
   ```
   Place this immediately after the stdlib import block and before any third-party imports, so all `os.environ.get(...)` module-level reads (lines 46-74) see the file's values.

3. **`parser-service/.env.example`** — create with every variable the service reads, values set to safe defaults/placeholders:
   ```
   PARSER_SERVICE_TOKEN=dev-secret-change-me
   OLLAMA_BASE_URL=http://localhost:11434
   LLM_MODEL=llama3
   EMBEDDING_MODEL=nomic-embed-text
   CHROMA_DIR=./chroma_db
   OLLAMA_TIMEOUT_SECONDS=120
   RELEVANCE_THRESHOLD=0.45
   RETRIEVAL_K_CHAT=5
   CHUNK_SIZE=1000
   CHUNK_OVERLAP=200
   # PARSER_PORT=8000   # override only if 8000 is taken; do NOT use PORT (collides with Node)
   ```

4. **`parser-service/.env`** — create (not committed) by copying `.env.example` and setting `PARSER_SERVICE_TOKEN=dev-secret-change-me`. This file must be gitignored.

5. **`.gitignore` check** — verify `parser-service/.env` is covered by the root `.gitignore`. If not, add `parser-service/.env` to it.

6. **Update `CLAUDE.md`** — in the "Parser service" section, add a setup step:
   ```bash
   cp parser-service/.env.example parser-service/.env   # then edit PARSER_SERVICE_TOKEN
   ```
   Make clear this is a one-time setup step needed before first run.

7. **Update `parser-service/README.md`** — add a "First-time setup" section above "Running the Service" that shows the `cp .env.example .env` step.
