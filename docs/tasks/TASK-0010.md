# TASK-0010: Persistent multi-file library for Course Material — show all indexed files

## Goal
The Course Material panel in Sanity Studio maintains a persistent, additive list of every file indexed into the AI backend, so editors can see all source assets across multiple upload sessions without any previous file being overwritten.

## Context
TASK-0008 wired multi-file uploads, but the Sanity field `courseMaterial` is still a `string` — each upload batch replaces the previous summary string. A course may have a `.pptx` (slides), `.xlsx` (spec sheet), `.docx` (manual), and a `.pdf` (datasheet) uploaded in separate sessions; right now only the last batch is visible. The fix requires two changes: (1) change the Sanity schema field from `string` to `array` of typed objects, and (2) rewrite `CourseFileUploadInput` to append to the array and render the full persistent list with a remove button per entry.

### Patterns in use
- `CourseFileUploadInput` receives `ArrayInputProps` — `value` is `UploadedFile[] | undefined` (Sanity may pass `undefined` when the array is empty).
- Use `value ?? []` as the persistent file list; it persists across browser refreshes and editing sessions because it is stored in the Sanity document.
- File upload loop is unchanged from TASK-0008: sequential `for...of`, one `POST /api/upload` per file, no `Promise.all`.
- After each successful upload, immediately append the record with `onChange(PatchEvent.from(insert([...], 'after', [-1])))` — do not batch all appends at the end, so partial success is saved.
- `@sanity/ui` components already imported: `Card`, `Stack`, `Box`, `Flex`, `Text`, `Badge`, `Button`. Add `Spinner` for the uploading state if desired (also available from `@sanity/ui`).
- The `_key` field on each item is managed by Sanity — do NOT generate or set it manually. Pass items without `_key`; Sanity assigns it on `insert`.
- `defineArrayMember` must be imported from `'sanity'` (already confirmed exported).

### Known constraints
- **Do not touch** `UploadResponseSchema`, `MAX_UPLOAD_BYTES`, or `/api/upload/route.ts`.
- **Do not touch** `parser-service/main.py` — `ALLOWED_EXTENSIONS` already includes `.xlsx` from TASK-0008.
- The old `string` field value on existing Sanity documents will simply be absent on the array field — `value ?? []` handles this gracefully; no migration script needed.
- **No `Promise.all`** for uploads — sequential only (Ollama serializes embedding calls).
- The remove button must call `onChange(PatchEvent.from(unset([{_key}])))` — do not call a parser service delete endpoint; ChromaDB re-upload already replaces chunks by filename (deterministic IDs), so stale chunks cause no harm.
- Keep the per-session `fileStatuses` state for the in-progress upload UX. The persistent list comes from `value` (Sanity document), not from component state.
