# TASK-0010: Restore premium visual effects with GPU-composited layer promotion

**Status:** todo
**Depends:** TASK-0009

## Goal
Restore the cinematic blur entrance, soft hotspot glow halos, and animated root background to full visual richness by applying layer promotion (`will-change: transform`, `translateZ(0)`) rather than removing the effects — so the premium feel is preserved at 60fps.

## Context
TASK-0009 removed several `filter` CSS effects (blur entrance, brightness/drop-shadow on completion, `blur-sm` halo on visited hotspots) on the grounds that `filter` causes GPU rasterize. That analysis was correct in the abstract but too aggressive in practice: **`filter` on an element that already has a `transform` or `will-change: transform` is composited by Chrome, Safari, and Firefox** — the element gets its own compositor layer and filter runs on the GPU. The TASK-0009 implementation removed the effects instead of layer-promoting the elements. This task restores them correctly.

The root shell animated gradient (`dynamic-gradient` on `bg-glass-gradient`) was correctly removed in TASK-0009 — `background-position` is never composited and that one stays gone. Everything else that was stripped should be evaluated and restored where it adds visual value without real-world jank.

### Exactly what was stripped in TASK-0009 (restore these)

#### 1. `filter: blur()` on stage entrance — restore with layer promotion

**Current state (after TASK-0009):**
```css
@keyframes stage-enter-product {
  0%   { transform: translateY(20px) scale(0.94); opacity: 0; }
  100% { transform: translateY(0) scale(1); opacity: 1; }
}
```

**Restore to (with GPU-safe blur):**
```css
@keyframes stage-enter-product {
  0%   { transform: translateY(20px) scale(0.94); opacity: 0; filter: blur(6px); }
  100% { transform: translateY(0) scale(1); opacity: 1; filter: blur(0px); }
}
```

**Also add to the element that carries `.stage-enter-product` in ProductStage.tsx:**
```tsx
// The outermost product wrapper div (className="stage-enter-product absolute ...")
// already has transform applied from parallax — add will-change to ensure layer promotion:
style={{ ..., willChange: 'transform, opacity, filter' }}
```

Note: the element already participates in Framer Motion transforms (`prodTranslateX/Y`) which promote it to its own compositing layer. The `filter` in the CSS animation will therefore run on that same GPU layer — no rasterize penalty.

### Patterns in use
- `will-change: transform` on a Framer Motion element is often redundant (Framer promotes automatically) but `will-change: filter` is not set automatically — add it explicitly on elements whose `filter` needs to be composited.
- Never add `will-change` to elements that are static — it wastes GPU memory. Only add it to the specific animated wrappers.
- `blur-sm` = `filter: blur(4px)` — on a static <24px element this is rasterized once and cached; it is NOT re-rasterized per frame.
- Run `npm run typecheck && npm run test` from `web/` before marking done.

### Known constraints
- **Do NOT restore `dynamic-gradient`** on `bg-glass-gradient` — `background-position` is never composited; the static gradient introduced in TASK-0009 is correct and stays.
- **Do NOT remove the `glowBackground` → `transform` fix from TASK-0009** — that was a legitimate optimization and stays.

- The `stage-enter-product` duration was changed from 0.9s → 0.65s in TASK-0009. Keep 0.65s — it is snappier and the right call regardless of blur.
