# TASK-0012: Add superscript support to all Portable Text editors and renderers

**Status:** done

## Goal
Add a `sup` (superscript) decorator to every Sanity block-text field in the schema and wire up the corresponding `<sup>` mark renderer in every frontend `PortableText` callsite so authored superscripts appear correctly in the player.

## Context
Several lesson body fields and hotspot/layer body fields use Sanity's Portable Text (`type: 'block'`). None of them expose a superscript decorator in the Studio toolbar, and none of the frontend `PortableText` renderers handle a `sup` mark. Content authors need superscript for spec callouts (e.g. "5G¹", "MHz²"). The fix is two-sided: schema (Studio toolbar) + renderer (player display).

## Affected Area
- Layer: cross-cutting (Sanity schema + Next.js frontend)
- Agent role: web-engineer

### Patterns in use
- Mark decorators in Sanity block definitions live under `marks.decorators` as `{ title: string, value: string }` objects.
- When `marks.decorators` is **omitted**, Sanity uses a built-in default set: `strong`, `em`, `underline`, `strike-through`, `code`. Once you add `decorators`, it **replaces** the defaults — so list them all.
- The `@portabletext/react` `PortableText` component accepts a `components` prop; mark renderers live under `components.marks.<decoratorValue>`.
- Export a single shared `supMark` constant from a new file `web/src/lib/portable-text-components.tsx` and import it at each callsite to avoid duplicating the inline `<sup>` element. Keep the file minimal — just the one export.
- `ContentLesson.tsx` already has a `components.marks` object; spread `supMark` into it rather than replacing it.

### Known constraints
- **Do not remove `layerLink` from `ContentLesson.tsx`** — it wires body text to open hotspot panels and is load-bearing.
- **After any schema change run:** `cd web && npx sanity@latest schema deploy`. The Studio will not show the new decorator until the schema is redeployed.
- **GROQ ↔ Zod parity rule** does not apply here — `portableTextSchema` in `contracts/sanity.ts` is already typed as `z.custom<PortableTextBlock[]>` (structurally loose); no contract change needed.
- **No `npm run typecheck` regressions** — `<sup>` is a standard HTML element; no extra type imports required.
