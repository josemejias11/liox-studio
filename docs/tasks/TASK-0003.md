# TASK-0003: Fix CSP source pattern so /studio gets the Studio policy

## Goal
Fix `next.config.ts` so the `/studio` route (no trailing slash) is served with `STUDIO_CSP` instead of `MAIN_CSP`, and add `https://accounts.sanity.io` to `STUDIO_CSP` so Studio authentication completes.

## Context
Sanity Studio is embedded at `/studio`. The `headers()` config in `next.config.ts` uses `source: '/studio/(.*)'` to apply `STUDIO_CSP`. That regex requires at least one character after `/studio/`, so the bare `/studio` path falls through to the catch-all `source: '/(.*)'` and receives `MAIN_CSP`. `MAIN_CSP` has `connect-src 'self'` which blocks every cross-origin request — including `https://e7l925v5.api.sanity.io`. The browser silently fails the XHR and Sanity's client reports `isNetworkError: true`. Sanity CORS is already configured correctly (`http://localhost:3000` with credentials); the blocker is purely the wrong CSP being served.

A secondary issue: even when the Studio CSP is applied on sub-paths, `frame-src 'self'` and `connect-src` both omit `https://accounts.sanity.io`, which is required for Studio's OAuth login flow.

### Relevant symbols

```ts
// web/next.config.ts — current STUDIO_CSP (lines 50–64) — two directives need updating
const STUDIO_CSP = [
  "default-src 'self'",
  "script-src 'self' 'unsafe-inline' 'unsafe-eval'",
  "style-src 'self' 'unsafe-inline'",
  `img-src ${SHARED_IMG_SRC}`,
  "font-src 'self' https://fonts.gstatic.com",
  "connect-src 'self' https://api.sanity.io https://*.api.sanity.io wss://*.api.sanity.io https://cdn.sanity.io",
  //            ↑ missing https://accounts.sanity.io
  "worker-src 'self' blob:",
  "frame-src 'self'",
  //          ↑ missing https://accounts.sanity.io (OAuth iframe)
  "frame-ancestors 'self'",
  "base-uri 'self'",
  "form-action 'self'",
]

// web/next.config.ts — current headers() wiring (lines 96–116)
async headers() {
  return [
    {
      source: '/studio/(.*)',   // ← BUG: does not match bare /studio
      headers: [
        ...COMMON_HEADERS,
        { key: 'Content-Security-Policy', value: STUDIO_CSP },
        { key: 'X-Frame-Options', value: 'SAMEORIGIN' },
      ],
    },
    {
      source: '/(.*)',          // catch-all — /studio falls here today
      headers: [...COMMON_HEADERS, { key: 'Content-Security-Policy', value: MAIN_CSP }],
    },
  ];
},
```

### Patterns in use
- CSP strings are arrays of directive strings joined with `'; '`.
- `STUDIO_CSP` is the relaxed policy; `MAIN_CSP` is the strict one. Do not blur the two.
- `source` uses Next.js path-to-regexp syntax — `:path*` matches zero-or-more segments and is the idiomatic way to match a prefix including the root.
- `COMMON_HEADERS` and `MAIN_CSP` must not be modified.

### Known constraints
- Do not add `https://accounts.sanity.io` to `MAIN_CSP` — it applies to the learner-facing app and must stay strict.
- Do not change `SHARED_IMG_SRC`, `COMMON_HEADERS`, or anything outside `STUDIO_CSP` and the `source` pattern.
- No new dependencies.

## Requirements

1. Change the Studio header source pattern from `'/studio/(.*)'` to `'/studio/:path*'` so that both `/studio` and `/studio/<anything>` are matched.
2. Add `https://accounts.sanity.io` to the `connect-src` directive in `STUDIO_CSP`.
3. Add `https://accounts.sanity.io` to the `frame-src` directive in `STUDIO_CSP`.
4. Verify with `curl -sI http://localhost:3000/studio | grep content-security-policy` that the response includes `*.api.sanity.io` and `accounts.sanity.io` in the CSP.
5. `npm run typecheck` must pass.
