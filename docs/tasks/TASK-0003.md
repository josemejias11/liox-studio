# TASK-0003: Fix scrollStory — remove nav lock and fix scroll rendering

## Goal
`scrollStory` lessons render correctly within LessonFrame (scroll works, sticky hero sticks, chapters reveal), navigation is not locked waiting for scroll completion, and progress is still tracked when the learner reaches 85%.

## Context
Two bugs exist. (1) **Lock**: `scrollStory` is grouped with `dragDrop` in `isSpecialLesson`, which locks the Next button until `markVisited('completed')` is called — this is the wrong model for a story lesson, where the learner should be free to advance at any time. (2) **Scroll broken**: `ScrollStoryLesson` uses `useScroll({ target: containerRef, offset: [...] })` which tracks scroll relative to the window/viewport. But MotoViewer wraps all screens in `<motion.div className="absolute inset-0">` inside LessonFrame whose content area is `overflow-clip` — so the page never actually scrolls. The scrollYProgress stays at 0 permanently. The component needs its own scrollable container. No CMS, GROQ, or Zod changes are needed — the schema, query, and contract are all already correct.

## Affected Area
- Layer: frontend
- Agent role: web-engineer

### Patterns in use
- `baseMarkVisited(lessonKey, label, totalCount)` — third arg is the total items required for completion. Pass `1` for single-completion lessons (scroll 85% = done).
- `isSpecialLesson` is the only flag that blocks `nextLocked` for non-hotspot lessons — removing `scrollStory` from it is the entire lock removal.
- `completionHint` text references `hotspots.length`; after the fix `nextLocked` will be false for scrollStory so the hint won't render, but guard the string against `hotspots.length === 0` to be safe.
- All component files are one-to-one with lesson types — don't touch other components.

### Known constraints
- `dragDrop` must stay in `isSpecialLesson` — its lock is intentional and required.
- Progress tracking for scrollStory must still work: call `baseMarkVisited(lessonKey, 'completed', 1)` directly from the `onComplete` callback (bypassing the shared `markVisited` wrapper which would pass `hotspots.length = 0` and silently skip the DB write because `totalHotspots > 0` would be false).
- `useScroll` must use `container:` (pointing to the scroll wrapper ref), not `target:` — switching to `container` tells framer-motion to track the element's own scroll position rather than its position relative to the viewport.
- The sticky hero's `h-screen` must become `h-full` so it fills the scroll container (not the full viewport), because the scroll container is shorter than the viewport (LessonFrame's nav bar reduces available height).
- Do not change `LessonFrame` — the scroll must be self-contained inside `ScrollStoryLesson`.
- Run `npm run typecheck` from `web/` before declaring done.

## Requirements

1. `isSpecialLesson` in `MotoViewer.tsx` is `dragDrop` only — `scrollStory` is removed.
2. The `scrollStory` case in `renderPhase()` calls `onComplete={() => baseMarkVisited(lessonKey, 'completed', 1)}` — not the shared `markVisited` wrapper.
3. `completionHint` is guarded: only rendered when `nextLocked && hotspots.length > 0`.
4. `ScrollStoryLesson` wraps its entire output in a `ref`-attached `<div>` with `className="relative w-full h-full overflow-y-scroll"` that becomes the scroll container.
5. `useScroll` is changed to `useScroll({ container: scrollContainerRef })` (no `target`, no `offset`) — `scrollContainerRef` is the new scroll-wrapper ref.
6. The sticky hero's outer div changes from `h-screen` to `h-full` so it fills the scroll container height.
7. Chapter blocks keep `min-h-screen` (100vh) — this is intentional: each chapter should require roughly one full scroll to traverse.
8. `npm run typecheck` exits 0 with no new errors.
