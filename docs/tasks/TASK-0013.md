# TASK-0013: Stacking-Cards Layout for ScrollStory Lesson

**Status:** todo

## Goal
Replace the current two-column (sticky image right / fading text left) layout of `ScrollStoryLesson.tsx` with a stacking-cards scroll effect where each `scrollChapter` is a `sticky` card that slides up and overlaps the previous one as the user scrolls — matching the visual language of `cv-portfolio/app/page.tsx`.

## Context
The user identified a "sections stack" pattern in their portfolio site (`http://localhost:3001/`) built in `cv-portfolio/app/page.tsx`. Each page section is a `sticky` rounded card with an incrementally larger `top` offset and higher `z-index`, separated by `mb-[50vh]` spacer margins. As the user scrolls, each card slides up and sits on top of the previous one, creating a layered deck effect. The user wants the `scrollStory` lesson type in moto-ai to use the same visual pattern for `scrollChapters`.

### Patterns in use

- `shouldReduceMotion = useReducedMotion()` — must be respected; disable all scroll-driven motion when true.
- `onComplete()` must fire when user reaches the last card (via IntersectionObserver on the last card at ≥0.5 threshold, or scroll progress > 0.85 — keep the scroll progress approach).
- `supMark` is imported from `@/lib/portable-text-components` — preserve for PortableText marks.
- Background color palette: `#0f0f11` (near-black), `#f5d061` (gold accent). Match these in the new card design (don't adopt the blue/slate palette from the portfolio verbatim).

## Requirements

1. **Container**: `ScrollStoryLesson` outer div keeps `ref={scrollContainerRef}`, `overflow-y-scroll`, `bg-[#0f0f11]`, full `w-full h-full`. Remove the fixed `containerHeight` and sticky hero image — they are replaced by the stacking layout.

2. **Progress bar**: Keep the `motion.div` progress bar at the top of the scroll container (`scaleX: scrollYProgress`, gold `bg-[#f5d061]`, `h-1`, `origin-left`).

3. **Stacking cards**: Render one card per `scrollChapter`. Each card must be:
   - `position: sticky` with `top` computed as `BASE_TOP_PX + index * STACK_STEP_PX` (use inline `style`; values `BASE_TOP_PX = 16`, `STACK_STEP_PX = 12` are reasonable starting points).
   - `zIndex: index + 1` (inline style).
   - `marginBottom: index < lastIndex ? '50vh' : '0'` — creates scroll space so each card sticks before the next arrives.
   - Visually: `rounded-3xl`, dark card background (e.g. `bg-[#1a1a1e]`), subtle border (`border border-white/10`), top-shadow (`shadow-[0_-20px_40px_-20px_rgba(0,0,0,0.8)]`).
   - Padding: `p-8 md:p-12`.

4. **Card content** (per chapter):
   - If `chapter.image?.asset?.url` exists: render a full-width rounded image above the text (`w-full`, `rounded-2xl`, `mb-6`, `object-cover`, fixed aspect ratio `aspect-video` or `aspect-[4/3]`).
   - Heading: `<h3>` styled like current — `text-4xl md:text-5xl font-serif mb-6 text-white`.
   - Body: same PortableText rendering with `supMark`, prose styles `text-white/70`.
   - No opacity/translateY framer-motion animation on the card itself (the sticky stacking is the interaction — card-level animation is unnecessary and distracting; `shouldReduceMotion` distinction is moot here).

5. **Chapter progress dots**: Keep the dot nav on the right side of the screen (fixed or absolute within the scroll container, `right-4`). Active dot determined by scroll position (existing `activeChapter` logic via `scrollYProgress`). Clicking a dot scrolls to that card using `scrollIntoView`.

6. **Completion**: `onComplete()` fires when `scrollYProgress > 0.85` (same as before — keep existing `useEffect` with the `scrollYProgress.on("change")` subscription).

7. **Completion overlay**: Keep the `AnimatePresence` + `CheckCircle2` overlay (it can be positioned `fixed` or `absolute` over the scroll container).

8. **Hero image fallback**: If there is a `lesson.media` image but no chapter images, show it once as a header image above the first card (outside the stacking flow, `w-full rounded-2xl mb-8`).

9. **Reduced motion**: When `shouldReduceMotion` is true, keep all cards fully visible with no scroll-driven effects. The sticky stacking is pure CSS and remains; no JS animation needed.
