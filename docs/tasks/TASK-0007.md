# TASK-0007: Fix parser service port — eliminate accidental binding to port 80

## Goal
`main.py` binds to port 8000 by default when invoked with `python main.py`, eliminating the `[Errno 13] permission denied` crash that occurs when uvicorn is launched without an explicit `--port` flag (port 80 is privileged on macOS/Linux).

## Context
The FastAPI parser service (`parser-service/main.py`) is a pure ASGI app with no `__main__` entry point — uvicorn must be started from the command line. The project-wide default port is **8000** (documented in `README.md`, `web/.env.example`, and `PARSER_SERVICE_URL`). The crash happens when the developer omits `--port 8000` and uvicorn defaults to port 80, which requires root on any Unix system.

The fix is to add a `if __name__ == "__main__"` guard that calls `uvicorn.run(app, host="127.0.0.1", port=8000, reload=True)`. This makes `python main.py` the canonical, no-argument launch command that is always on the right port. The existing `uvicorn main:app --host 0.0.0.0 --port 8000 --reload` command still works unchanged.

### Patterns in use
- `uvicorn` is already declared in `requirements.txt` — no new dependency.
- The app uses `PARSER_SERVICE_TOKEN` required at startup — the `__main__` guard must not bypass the `lifespan` handler.
- `reload=True` mirrors the existing README command (`--reload`) for parity in dev.
- `host="127.0.0.1"` (loopback-only) for the default `python main.py` path; external exposure still available via the explicit `uvicorn` command with `--host 0.0.0.0`.

### Known constraints
- Do **not** hardcode a port anywhere other than the `__main__` guard. Operators who need a different port still override via the CLI.
- Do **not** change any route, model, or middleware logic.
- The `lifespan` handler raises `RuntimeError` when `PARSER_SERVICE_TOKEN` is unset — this must still fire normally.
