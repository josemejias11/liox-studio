# TASK-0007: Fix hotspot positioning accuracy and high-res image quality

**Status:** todo

## Goal
Hotspot pins render at the exact pixel they were placed in the CMS editor for both ContentLesson and ProductStage, and product images are served at an appropriate resolution rather than the original full-size file.

## Context
Two separate coordinate-space mismatches cause hotspot pins to render far from where the author placed them:
1. **ContentLesson** shows the image at its natural aspect ratio in the CMS editor (`<img width:100%>`), but renders it with `object-cover` in a full-screen landscape frame in the player. A hotspot placed at y=30% in a portrait image in the editor ends up at 30% of the player height — nowhere near the intended feature.
2. **ProductStage** renders the product image with `h-[78vh] w-auto object-contain` centered in the stage, but hotspot pins are positioned as percentages of the full stage container, not the image's actual rendered bounds. A pin at x=30% lands 30% across the full screen, not 30% across the image.

Additionally, ProductStage renders the product image with `<Image width={1200} height={1200}>` without a Sanity loader or `sizes` prop, so Next.js cannot optimize it — high-res PNGs are served unresized.

The fix is frontend-only. The author wants no dependency on CMS changes (Sanity may be swapped out).

## Affected Area

- Agent role: web-engineer

- `sanityImageLoader` is imported from `@/lib/sanity-image-loader` — never inline CDN URL params manually.
- Hotspot x/y are percentages 0–100 stored as numbers, rendered as `left: ${x}%, top: ${y}%`.

### Known constraints
- **Do NOT change the `x/y` data contract** — values must stay as 0–100 percentages. The fix is purely in how those coordinates are applied in CSS.
- **ProductStage parallax**: The product image moves with mouse/gyro via Framer Motion transforms. The hotspot layer must move with the image. Currently the hotspots are outside the parallax `<motion.div>` — that is acceptable for now (do not address parallax-hotspot sync in this task, it is a separate scope).
- **No new dependencies** — use `useRef`, `useState`, `useEffect` + `ResizeObserver` (browser built-in). Do not add a library.
- **Backward compat with ProductStage coordinates**: Since all content was wiped in TASK-0006, there are no legacy coordinates to migrate. Author will re-enter hotspot positions after this fix is deployed.

## Requirements

### 1 — Fix HotspotMapInput preview to 16:9 with object-cover (ContentLesson alignment)
Change the CMS editor preview container to enforce a 16:9 aspect ratio and display the image with `objectFit: cover`. Coordinates captured in the editor will then be in the same coordinate space as the ContentLesson player. The container already uses `containerRef.getBoundingClientRect()` for coordinate capture — no change to capture logic needed, only the container style and image style.

**Before:**
```tsx
// container
style={{ position: 'relative', borderRadius: 8, overflow: 'hidden', ..., minHeight: 140 }}
// image
<img style={{ display: 'block', width: '100%', pointerEvents: 'none' }} />
```

**After:**
```tsx
// container — enforce 16:9 via padding-bottom trick
style={{ position: 'relative', borderRadius: 8, overflow: 'hidden', ..., paddingBottom: '56.25%', minHeight: 0 }}
// image — fill the padded box with object-cover
<img style={{ position: 'absolute', inset: 0, width: '100%', height: '100%', objectFit: 'cover', pointerEvents: 'none' }} />
```

Update the no-image placeholder div to also be `position: absolute; inset: 0` so it fills the same padded container.

### 2 — Fix ProductStage hotspot layer to follow actual image bounds (ProductStage alignment)

Use a `ref` on the image's innermost wrapper `<div>` (the breathe/spin div that directly wraps `<Image>`) and a `ResizeObserver` to track the image element's rendered bounds relative to the stage container.

Store `imageRect: { left: number; top: number; width: number; height: number } | null` in state, initialized to `null`.

Move the hotspot rendering from outside the parallax structure into a new `<div>` that overlays exactly the image's bounds:

```tsx
// Hotspot layer — anchored to image bounds, not full stage
{imageRect && hotspots.map((h, i) => (
  <div
    key={h._key}
    className="absolute pointer-events-none"
    style={{
      left: imageRect.left,
      top: imageRect.top,
      width: imageRect.width,
      height: imageRect.height,
      zIndex: 10,
    }}
  >
    <div
      className="absolute"
      style={{
        left: `${h.x}%`,
        top: `${h.y}%`,
        opacity: entered ? 1 : 0,
        transform: entered ? 'scale(1)' : 'scale(0.2)',
        transition: `opacity 0.4s ease-out ${240 + i * 110}ms, transform 0.5s cubic-bezier(0.34, 1.56, 0.64, 1) ${240 + i * 110}ms`,
        pointerEvents: 'auto',
      }}
    >
      <Hotspot x={0} y={0} label={h.label} ... />
    </div>
  </div>
))}
```

`imageRect` should be measured relative to `containerRef` (the existing `containerRef` in ProductStage, which wraps the whole stage with `onMouseMove`). Use `entry.contentRect` from ResizeObserver on the image wrapper to get dimensions, and `getBoundingClientRect()` for position relative to the stage container.

While `imageRect` is null (before first measurement), fall back to the current full-container positioning so hotspots at least render during SSR/hydration.
