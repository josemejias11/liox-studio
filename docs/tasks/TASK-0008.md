# TASK-0008: Multi-file upload with XLSX support for Course Material

## Goal
The Course Material uploader in Sanity Studio accepts multiple files at once (PDF, PPTX, DOCX, **XLSX**) and uploads them sequentially, showing per-file progress, so content editors can bulk-load specification sheets in one action.

## Context
Specification sheets are the bulk of course material and arrive as `.xlsx` files. The current uploader (`CourseFileUploadInput.tsx`) is single-file only and rejects `.xlsx`. MarkItDown (`markitdown[all]`) already handles Excel files — no new Python dependency is needed. The parser service's `ALLOWED_EXTENSIONS` constant is the only backend gate that blocks `.xlsx`. The Next.js proxy route (`/api/upload`) is already correct for single-file calls and does not need to change — the frontend will fan-out one `POST /api/upload` per file.

## Affected Area
- Layer: frontend + API (parser service config only — no route logic change)
- Agent role: web-engineer

### Patterns in use
- `CourseFileUploadInput` is a Sanity custom input — it receives `{ value, onChange }` from `StringInputProps`. The `value` string is stored in the `courseMaterial` field of the `course` document and is display-only (used as a status memo for the editor, not consumed by learners).
- `onChange(set(str))` updates the Sanity string field. For multi-file, build a summary string after all uploads complete: e.g. `"3 files: spec.xlsx (45 chunks), guide.pdf (12 chunks), deck.pptx (8 chunks)"`.
- The Sanity UI component library (`@sanity/ui`) is already imported: `Stack`, `Box`, `Flex`, `Text`, `Badge`, `Button`, `Card`. Use `Badge` with `tone="positive"` / `tone="critical"` / `tone="caution"` for per-file status.
- The fetch call structure is already correct for a single file — wrap it in a `for...of` loop over `Array.from(event.target.files)` to upload sequentially (not parallel — the parser service runs a single Ollama instance and can't handle concurrent embedding calls without queuing issues).
- `CourseFileUploadInput` is wired into `course.ts` schema at field `courseMaterial` as `components: { input: CourseFileUploadInput }` — no schema change needed.

### Known constraints
- **Sequential uploads only** — do not use `Promise.all`. The local Ollama instance serializes embedding calls; concurrent uploads cause timeouts.
- **Per-file 50 MB cap** is enforced both in the component (`MAX_UPLOAD_BYTES`) and in the Next.js route. Keep both checks — the component check is a fast client-side gate.
- The `<input>` element must be reset after each selection (`event.target.value = ''`) so the same files can be re-uploaded after an error.
- Do not change `/api/upload/route.ts` — it correctly handles one file per POST. Do not introduce a batch endpoint.
- Do not change `UploadResponseSchema` or `ParserUploadResponseSchema` in `parser-service.ts` — wire contract is correct.
- `markitdown[all]` in `requirements.txt` already pulls in Excel support (`openpyxl`). No new Python dependency needed.

## Requirements
1. `parser-service/main.py`: `ALLOWED_EXTENSIONS` includes `".xlsx"`.
2. `CourseFileUploadInput.tsx`: `<input>` has `multiple` attribute and `accept=".pdf,.pptx,.docx,.xlsx"`.

8. The "Select Files" button label updates to reflect multi-file support.
