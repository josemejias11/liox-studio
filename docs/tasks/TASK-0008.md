# TASK-0008: Design audit — motion quality, interaction smoothness, and animation polish

**Status:** todo

## Goal
Produce a concrete, code-level design specification (`docs/tasks/TASK-0008-design-spec.md`) that documents which animations to keep, tune, or remove, with exact timing/easing values and interaction pattern improvements the web-engineer can implement directly in TASK-0009.

The player has a rich animation system (Framer Motion transitions, CSS keyframe stages, parallax, completion bursts, hotspot pulse rings) built over multiple sprints. No holistic design review has been done. The owner wants the app to feel notably smoother — especially lesson-to-lesson transitions, hotspot discovery, and the ProductStage entrance. The designer's output feeds directly into TASK-0009 implementation.

### Known technical constraints (pass to TASK-0009 implementer)
- All CSS animations that animate `transform` or `opacity` only are GPU-composited — keep these.
- `filter: blur()`, `filter: brightness()`, `filter: drop-shadow()` force GPU rasterize — flag these for removal or replacement.
- `background` property changes (including `background-position`) are **not** GPU-composited — they repaint the layer on every frame.
- The `glowBackground` motion value in `ProductStage.tsx` writes to `background` (a `radial-gradient(…at X% Y%…)`) on every `mousemove` — it repaints every frame.
- `backdrop-blur-xl` on `.glass-panel` (used widely) forces compositing of everything behind each panel — limit simultaneous panels with heavy blur.
- `prefers-reduced-motion` is handled globally in `globals.css` — individual animations don't need their own guard.

## Requirements for the design-spec output

The output file `docs/tasks/TASK-0008-design-spec.md` must contain the following sections:

### 1. Lesson navigation transition
Review `slideVariants` (x: ±50%, opacity, 0.35s). Evaluate:
- Does 50% translate feel physically correct or too far/fast?
- Is 0.35s the right duration for a forward/backward page flip?
- Would a cross-fade (`opacity` only) feel smoother than a slide?
- Recommend: keep `x` slide / replace with scale+fade / use asymmetric easing.
- Output: exact Framer Motion `variants` object and `transition` values to use.

### 2. ProductStage entrance sequence
Review all `stage-enter-*` animations that fire sequentially on mount.
- Is the 0.9s `stage-enter-product` with `blur(8px)` entrance justified, or is it visually heavy?
- Does the bg (0.7s) → product (0.9s delay 0.08s) → UI labels (0.5s) stagger feel natural?
- Flag `filter: blur(8px)` for removal (perf + may look muddy on low-res screens).
- Recommend: revised duration, delay cascade, and easing for each enter animation.
- Output: updated CSS keyframe specs (name → duration, easing, delay, and properties).

### 3. Hotspot pulse rings
Review 3 concurrent infinite `stage-wave` animations per unvisited hotspot.
- Does 3 rings add value vs. visual noise?
- 2.4s cycle — is it calm enough or anxious?
- Recommend: number of rings (1/2/3), `animation-duration`, scale target (`2.8` → ?), opacity curve.
- Output: updated `.stage-ring` CSS.

### 4. ProductStage completion animation (spin/rise)
- Review `stage-spin-anim` (scale + drop-shadow + brightness pulse, 1.4s spring) and `stage-rise-anim` (rise 24px + scale 1.02, 1.2s).
- Flag `filter: drop-shadow + brightness` (repaint per frame).
- Recommend: replacement that avoids filter animation (e.g., a glow overlay div that fades in/out via opacity instead of a drop-shadow filter).
- Output: replacement keyframe spec.

### 5. Ambient background gradient (LessonFrame root)
- `bg-glass-gradient` runs infinite `background-position` animation on the root shell — always painting.
- Evaluate: does the subtle gradient movement add enough value to justify the perf cost?
- Recommend: keep (with `will-change: background-position`) / reduce to 60s cycle / replace with static gradient / remove.
- Output: explicit recommendation + updated CSS if keeping.

### 6. Discovery panel (hotspot detail slide-in)
- Review `DiscoveryPanel.tsx` open/close animation (read the component).
- Evaluate: does it feel punchy or laggy on first open?
- Recommend: timing and easing for open/close.
- Output: CSS/Framer values.

### 7. CompletionBurst
- Multiple burst rings expand simultaneously. Flag if the animation feels excessive for a training context.
- Recommend: keep / simplify (fewer rings, shorter duration).

### 8. General interaction micro-feedback
- `Hotspot` button: `whileHover: scale(1.15)`, `whileTap: scale(0.9)`, spring `stiffness: 400 damping: 17`. Evaluate feel.
- Nav button hover/active states in `LessonFrame.tsx`.
- Recommend spring params for each.

### 9. Mobile considerations
- The player is likely used on phones (320–390px wide).
- Evaluate whether the hotspot size (24px dot, 3 rings) is touch-friendly and visible on small screens.
- Recommend minimum touch target size and any mobile-specific animation tuning.
