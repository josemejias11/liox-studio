# TASK-0015: Improve scroll story lesson — per-chapter images, progress dots, completion state, and CMS clarity

## Goal
Make the scroll story lesson type useful and understandable: add per-chapter image support so each scroll beat can show a different product view, add chapter progress dots and a visible completion state to the component, and fix the CMS editing experience so editors know what to fill in.

## Context
The scroll story format is a parallax lesson: one sticky hero image animates (scale/rotate/translate) as the learner scrolls through a series of text chapters. The concept is solid but two problems make it confusing. First, the CMS is misleading — the "Content" tab shows generic `Headline` and `Body Copy` fields shared by all lesson types; for scroll story, `Body Copy` is never rendered (the real content lives in `scrollChapters` in the "Interactions" tab), so editors think that's all there is. Second, the component itself has no per-chapter image support (all chapters must share the same background), no visible chapter progress, and no explicit completion state — scrolling past 85% silently marks it done with no feedback.

## Affected Area
- Layer: frontend + Sanity schema (cross-cutting)

### Patterns in use
- `opt()` helper in `sanity.ts` wraps nullable types: `opt(imageSchema)`.
- `imageSchema` is already defined in `sanity.ts`; reference it directly, do not redefine.
- `scrollChapters` items are anonymous `object` types in lesson.ts (not `defineArrayMember` — keep the same style).
- Sanity `hidden` callbacks take `({ parent })` — the existing `body` field visibility can be suppressed for scrollStory: `hidden: ({ parent }) => parent?.lessonType === 'scrollStory'` on the top-level lesson `body` field (line ~29 in lesson.ts).
- Per-chapter image should be resolved as the most recent non-null image: if chapter N has no image, display whatever image chapter N-1 (or the lesson hero) set. Track `activeImageUrl` as derived state.
- The `activeChapter` state already exists for reduced-motion support — reuse it as the single source of truth for both the progress dots and the active image.
- The existing sticky container uses `className="sticky top-0 h-screen w-full overflow-hidden flex items-center justify-center -z-10"` — keep z-index and positioning unchanged.
- Completion overlay should sit at `z-20` inside the sticky container, visible only when `isCompleted`.
- `framer-motion`'s `AnimatePresence` + `motion.div` is already imported — use it for image crossfades and the completion overlay.

### Known constraints
- Do not change the `targetScale` / `targetRotation` / `targetX` / `targetY` field names — they are referenced by name in the component's `useTransform` calls.
- The global image-transform animation (`scale`, `rotate`, `x`, `y` from `useTransform`) must continue to work regardless of whether per-chapter images are used. The per-chapter image is an image URL swap, not a replacement for the transform system.
- The reduced-motion path (`shouldReduceMotion`) must continue to work: when reduced motion is enabled, image transitions should be instant (`duration: 0`), not animated.
- Do not touch `MotoViewer.tsx` or `useCourseNavigation.ts` — scroll story completion is handled via the existing `onComplete` callback.
- `npm run typecheck` must pass with zero new errors.

## Requirements

1. **Sanity schema** (`lesson.ts`):
   - Add an `image` field (type `image`, `options: { hotspot: true }`) to each `scrollChapter` object, after `body` and before `targetScale`. Description: `'Overrides the hero image for this chapter. Leave blank to inherit the previous chapter's image.'`
   - Add descriptions to the transform fields: `targetScale` → `'1 = original size. 1.2 zooms in 20%.'`, `targetRotation` → `'Degrees. Positive = clockwise.'`, `targetX` / `targetY` → `'Pixel offset from centre. Positive X moves right; positive Y moves down.'`
   - Hide the top-level lesson `body` field when `lessonType === 'scrollStory'` by adding `hidden: ({ parent }) => parent?.lessonType === 'scrollStory'` to the `body` field definition (prevents editor confusion — scrollChapters own the content for this type).

2. **Zod contract** (`sanity.ts`): Add `image: opt(imageSchema)` to the `scrollChapters` array item schema. Do not change any other field.

3. **GROQ query** (`queries.ts`): Extend `scrollChapters[]` projection to `{ heading, body, image { asset->{ url } }, targetScale, targetRotation, targetX, targetY }`.

4. **Component — per-chapter image** (`ScrollStoryLesson.tsx`):
   - Derive `activeImageUrl` from `activeChapter`: walk backwards from the active chapter to find the nearest chapter with an `image?.asset?.url`; fall back to `media?.asset?.url` if none found.
   - Replace the single static `<Image>` with an `<AnimatePresence mode="wait">` keyed by `activeImageUrl` that crossfades between images (`opacity: 0 → 1` on enter, `0` on exit, `duration: 0.4`; `duration: 0` when `shouldReduceMotion`).
   - The motion transform (`style={{ scale, rotate, x, y }}`) stays on the wrapper `motion.div`, not the individual image — the animation still applies to the current image.

5. **Component — chapter progress dots** (`ScrollStoryLesson.tsx`):
   - Render a column of dots fixed to the right edge of the sticky container: one dot per `scrollChapter`, the active one filled accent, others outlined.
   - Position: `absolute right-3 top-1/2 -translate-y-1/2 z-20 flex flex-col gap-2`.
   - Only render when `scrollChapters.length > 1`.

6. **Component — completion overlay** (`ScrollStoryLesson.tsx`):
   - When `isCompleted` becomes true, show a brief overlay inside the sticky container: a `CheckCircle2` icon (from lucide-react) + "Complete" label, centred, `z-20`, fading in with `motion.div initial={{ opacity: 0 }} animate={{ opacity: 1 }}`, auto-fading out after 1.5 s (`exit={{ opacity: 0 }}`). Use `AnimatePresence` to unmount it after the exit.

7. `npm run typecheck` passes with zero new errors.
