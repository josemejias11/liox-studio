### Patterns in use
- Prisma client is imported from `@/lib/db` — never import `@prisma/client` directly.
- Sanity write client (token-bearing, no CDN) is used for mutations — see `web/src/sanity/lib/client.ts` or similar. Do not use the CDN `readClient` for deletes.
- All `npx sanity` CLI commands must be run from `web/` (per `web/sanity.cli.ts`).
- Scripts live in `web/scripts/` (create the directory if it doesn't exist).
- Run `npm run typecheck && npm run test` from `web/` before declaring done.

### Known constraints
- **Do NOT drop the database or delete the Sanity dataset.** Truncate tables and delete documents — leave the schema and dataset intact so the app can be restarted immediately and new content entered.
- **Cascade order matters for Postgres.** Truncate child tables before parents, or use `TRUNCATE … CASCADE`. The safe FK order is: QuizAttempt → LessonProgress → HotspotVisit → GeneratedQuiz → Session.
- **Sanity drafts.** Every published document may have a `drafts.<id>` shadow. The delete script must target both `*[_type == "course"]` and the draft equivalents, or use `*[_type in ["course","chapter",...]]` which covers both because Sanity GROQ matches on `_type` regardless of draft prefix.
- **Sanity project/dataset:** project `e7l925v5`, dataset `production` (from `web/.env` and `web/sanity.cli.ts`).
- **Sanity WRITE_TOKEN** must be in env. Check `web/.env` for `SANITY_API_TOKEN` or `SANITY_WRITE_TOKEN`.
- **ChromaDB path:** `parser-service/chroma_db/` — simply delete the directory. The parser-service recreates it on next upload.
- **Do not delete parser-service eval fixtures** (`parser-service/eval/`) — those are baseline data for future RAG eval.
