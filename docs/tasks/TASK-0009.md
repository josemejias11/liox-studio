# TASK-0009: Fix Sanity Studio CSP — allow npm registry fetch for version check

## Goal
The `TypeError: Failed to fetch` console error on `/studio` is silenced by adding `https://registry.npmjs.org` to the Studio path's `connect-src` CSP directive in `next.config.ts`.

## Context
Sanity Studio v5 performs a background version check against the npm registry (`https://registry.npmjs.org/sanity/latest`) on load. The project's `next.config.ts` defines a bespoke CSP for the `/studio/*` path with `connect-src` limited to Sanity's own API and CDN hostnames — `registry.npmjs.org` is absent. The browser enforces the policy, blocks the fetch, and logs `TypeError: Failed to fetch`. The fix is a single hostname addition to `STUDIO_CSP`; no changes outside `next.config.ts` are needed.

### Patterns in use
- `STUDIO_CSP` is a plain string built from an array joined with `'; '` — add the new hostname at the end of the `connect-src` value, space-separated.
- `MAIN_CSP` must NOT be changed — the main app has no reason to reach `registry.npmjs.org`.
- The two CSP strings are applied in the `headers()` async function: Studio at `/studio(.*)`, main app at `/((?!studio).*)`.

### Known constraints
- Do not touch `MAIN_CSP` — only `STUDIO_CSP`.
- Do not add `registry.npmjs.org` with a wildcard (`*.npmjs.org`) — scope it exactly to `https://registry.npmjs.org`.
- No other files need to change.
