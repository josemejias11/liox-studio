### Patterns in use
- All motion values that write to `transform` or `opacity` only are GPU-composited — keep this constraint.
- `useMotionValue` + `useSpring` + `useTransform` write directly to styles without React re-renders — keep this pattern, just change WHAT property they write to.
- CSS keyframe animations are in `globals.css` — do not move them inline.
- `sanityImageLoader` is already wired globally via `next.config.ts` (`images.loaderFile`) — all `<Image>` components use it automatically.
- Run `npm run typecheck && npm run test` from `web/` before marking done.

- **Do not remove `prefers-reduced-motion` block** in `globals.css` — it is the accessibility safety net.
- **Do not change the `sanityImageLoader`** — it is already optimal.
- **`bg-glass-gradient` decision follows TASK-0008 recommendation** — read the design spec's §5 before acting. If the spec says remove, remove the class and CSS. If it says keep, add `will-change: background-position`.

### 2. Fix: `glowBackground` — replace `background` motion with `transform`-based approach
The ambient glow in ProductStage must NOT update the `background` CSS property on every frame. Replace with a fixed `radial-gradient` div that moves using `transform: translate()`:

```tsx
// Replace the motion.div with style={{ background: glowBackground }}
// with a static gradient div + a motion.div using transform for position

const glowTranslateX = useTransform(glowX, (v) => `${v * 10}%`);
const glowTranslateY = useTransform(glowY, (v) => `${v * 7}%`);

<div
  className="pointer-events-none absolute inset-[-50%]"
  style={{ background: 'radial-gradient(ellipse 62% 52% at center, rgba(104,91,199,0.09), transparent)' }}
>
  <motion.div
    className="absolute inset-0"
    style={{ x: glowTranslateX, y: glowTranslateY }}
  />
</div>
```

Actually: simplest GPU-safe fix is to move the entire gradient `<div>` using `transform: translate()` — keep gradient static, move the container. This keeps the `background` static (no repaint) while the position updates via GPU-composited `transform`.

### 3. Fix: remove `filter` from entrance and completion animations
In `globals.css`:
- **`stage-enter-product`**: Remove `filter: blur(8px)` from 0% keyframe and `filter: blur(0)` from 100%. Keep `translateY + scale + opacity` only.
- **`stage-product-spin`**: Remove `filter: drop-shadow(...) brightness(...)`. Replace the glow/brightness effect with an overlay `<div>` that pulses `opacity` instead (GPU-composited). Or simply keep just `scale` animation.
- **`stage-product-rise`**: Remove `filter: brightness(1.08)` — keep just `translateY + scale`.

In `ProductStage.tsx`: Remove any `style={{ filter: ... }}` applied inline (check completion state code).

### 4. Fix: `bg-glass-gradient` — follow TASK-0008-design-spec §5 recommendation
If the design spec says remove: delete `.bg-glass-gradient` from `globals.css` and replace the class with a static `bg-background` in `LessonFrame.tsx`.
If keep: add `will-change: background-position` to the `.bg-glass-gradient` rule.

### 5. Fix: font-display for MotoSans
Add `font-display: optional` to both `@font-face` declarations in `globals.css`:
```css
@font-face {
  font-family: 'MotoSans';
  font-display: optional;
  ...
}
```
`optional` is preferred for a brand font — if not cached, the browser uses the fallback immediately and upgrades on next load. This eliminates FOIT.

### 6. Fix: Sanity course fetch — add revalidation
In `web/src/app/course/[slug]/page.tsx`:
```ts
const raw = await readClient.fetch<unknown>(
  COURSE_BY_SLUG_QUERY,
  { slug: resolvedParams.slug },
  { next: { revalidate: 300 } }  // revalidate every 5 min; Sanity CDN is the authoritative source

```
This ensures Vercel edge cache is updated periodically rather than serving stale course data indefinitely.
