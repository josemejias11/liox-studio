# TASK-0005: Clean up deprecated config traces and create .env.example

## Goal
Delete SQLite leftover files, rewrite `web/.env` to reflect the local-dev setup, fix a stale comment in `parser-service.ts`, and commit a `web/.env.example` that documents every variable so any developer can onboard without guessing.

## Context
The project originally used SQLite, then Supabase, and now local PostgreSQL. Three layers of stale traces remain: binary SQLite files in `prisma/`, a `.env` whose header comments still describe Supabase connection params, and a comment in `parser-service.ts` that says "Ollama on AWS" (which is the prod target, not the local-dev default). Additionally there is no `.env.example` in the repo — a new developer has no reference for what variables are needed or what values to use locally. The goal is `dev` branch = copy `.env.example` → `.env.local`, run `npm install`, done.

### Patterns in use
- `.env*` is gitignored globally — `.env.example` must NOT match that glob. Confirm the pattern before creating the file. If `.env*` catches it, name the file `env.example` instead and note in the commit.
- `.env` holds non-secret local defaults; `.env.local` holds secrets (gitignored). Both are loaded by Next.js; `.env.local` overrides `.env`.
- `prisma/*.db*` files are already covered by `*.db`, `*.db-shm`, `*.db-wal` entries in `web/.gitignore` — the delete is safe, no gitignore change needed.

### Known constraints
- Do not change any variable names — they are consumed by code and Prisma.
- Do not remove `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` — they are needed for production and gracefully no-op in dev.
- The actual credential values (`josemejias:josemejias`, the Sanity token, etc.) must NOT appear in `.env.example` — use placeholder strings like `<your-local-pg-password>`.
- `NEXT_PUBLIC_SANITY_PROJECT_ID` and `NEXT_PUBLIC_SANITY_DATASET` are safe to keep real in `.env.example` (they are public, non-secret project identifiers).
