# TASK-0005: Sanity CMS integration health check

**Status:** todo

## Goal
Verify that the Sanity CMS integration is healthy end-to-end: env config set, schema deployed, GROQ queries return valid data, and Zod contracts remain in parity with both the queries and the Studio schema.

## Context
The Sanity layer is the content backbone of the entire product. Three independent
things must be true simultaneously: the Studio schema (source of truth for authors),
the GROQ queries (projection), and the Zod contracts (runtime validation) must all
agree on field names, types, and the `lessonType` enum. A silent drift in any one
of them causes runtime Zod coercions to silently swallow fields or crash the course
viewer. This task is a structured point-in-time audit — not a feature.

## Affected Area
- Layer: cross-cutting (CMS → API → frontend contract chain)
- Agent role: qa-automation-engineer

### lessonType enum — must be identical in both places

Studio schema (`schemaTypes/lesson.ts`, line 111–121):
```
content | interaction | stage | video | quiz | colorSwitcher | splitScreen | dragDrop | scrollStory
```

Zod contract (`contracts/sanity.ts`, line 90):
```ts
z.enum(['content', 'interaction', 'stage', 'video', 'quiz', 'colorSwitcher', 'splitScreen', 'dragDrop', 'scrollStory'])
```
**These are currently in sync** — the check must confirm they stay that way after any future schema edits.

### Patterns in use
- `opt()` in `contracts/sanity.ts` normalizes `null → undefined` for any nullable GROQ field. A field in the GROQ projection that can be `null` must use `opt()` in the Zod schema.
- `readClient` (CDN, no token) is used for all content reads — the health check must use this client, not `sanityClient`.
- `QUIZ_GRADING_QUERY` is SERVER-ONLY; the check must confirm it is NOT imported anywhere outside `app/api/quiz/grade/route.ts`.
- Sanity project ID: `e7l925v5`, dataset: `production`.

### Known constraints
- Do not log or print full env var values — confirm presence only (e.g., `!!process.env.SANITY_API_TOKEN`).
- Do not publish or mutate any documents — read-only checks only.
- Do not change any production code during this task — output a written report only.
- If `SANITY_API_TOKEN` is absent, the write client is non-functional but read operations still work; note this as a warning, not a failure.

## Requirements

1. **Env var presence check** — confirm all Sanity-related env vars from `.env.example` are present in `.env.local`: `NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET`, `SANITY_API_TOKEN`.

2. **Live GROQ round-trip** — run `COURSES_QUERY` against the `production` dataset using `readClient` and confirm at least one document is returned; validate the first result against `courseSummarySchema` and report pass/fail.

3. **GROQ → Zod field parity** — for each GROQ fragment, list every projected field and confirm a corresponding field exists in the Zod schema (by name). Flag any field present in GROQ but absent from Zod, and vice versa.

4. **lessonType enum sync** — extract the `list` values from `schemaTypes/lesson.ts` and the `.enum()` array from `contracts/sanity.ts` and confirm they are identical sets.

5. **Quiz answer isolation** — grep the codebase to confirm `QUIZ_GRADING_QUERY` is imported only in `web/src/app/api/quiz/grade/route.ts`. Any other import is a critical finding.

6. **Schema deployment status** — run `cd web && npx sanity@latest schema extract --path /tmp/schema-check.json` and compare the deployed type names against `schemaTypes/index.ts`. Flag any type registered in the Studio but missing from the deployed schema (or vice versa).

7. **TypeScript compilation** — run `npm run typecheck` from `web/` and confirm zero errors. A typecheck failure is a blocker.

8. **Output a written report** — produce `docs/tasks/TASK-0005-results.md` with:
   - Pass/fail for each requirement above
   - Any field drift found (GROQ field present in query but absent from Zod, or vice versa)
   - Any enum mismatch
   - Any QUIZ_GRADING_QUERY import violations
   - Recommended remediation for each finding, if any
