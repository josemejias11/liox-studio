# TASK-0001: Switch from Supabase to local PostgreSQL for development

## Goal
Replace the placeholder Supabase connection strings in `.env` and `.env.local` with a locally-running PostgreSQL instance (provisioned via WebStorm's built-in Database tool) so the app runs fully offline without any cloud dependency during development.

## Context
The project uses Prisma 5 with a PostgreSQL provider. The current `.env` contains template Supabase URLs that have never been filled in — the app cannot start a database connection today. The developer wants to swap those URLs for a local Postgres instance that WebStorm creates and manages. No code changes are needed outside of env files and one Prisma config check; this is purely a local-dev environment task.

## Affected Area
- Layer: DB / infra (local dev only)
- Agent role: `api-services-engineer`

## Codebase Context

### Entry-point files

| File | Why it matters |
|------|----------------|
| `web/.env` | Contains the two Supabase placeholder URLs that must be replaced |
| `web/.env.local` | Dev overrides — the real local credentials should land here (`.env.local` is gitignored) |
| `web/prisma/schema.prisma` | Declares `DATABASE_URL` (pooled) + `DIRECT_URL` (direct) env vars; both must resolve |
| `web/src/lib/db.ts` | Prisma singleton — no changes needed, but must be confirmed to boot cleanly |
| `web/package.json` | Contains `db:migrate:dev` and `db:migrate` scripts the agent will run to apply migrations |
| `web/prisma/migrations/20260611000000_init_postgres/migration.sql` | Existing migration that creates all 5 tables — must apply cleanly against the local DB |

### Relevant symbols

```prisma
// web/prisma/schema.prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")    // pooled (PgBouncer) URL for runtime queries
  directUrl = env("DIRECT_URL")      // direct connection for migrations only
}
```

```ts
// web/src/lib/db.ts
import { PrismaClient } from '../generated/prisma';
export const prisma = globalForPrisma.prisma ?? new PrismaClient({ ... });
```

### Patterns in use
- `DATABASE_URL` is consumed by Prisma at runtime; `DIRECT_URL` is used only by `prisma migrate`.
- Local secrets go in `.env.local` (gitignored) — never commit real credentials to `.env`.
- Migration script is `npm run db:migrate:dev` (calls `prisma migrate dev`).
- Prisma client is regenerated with `npm run db:generate` (calls `prisma generate`).

### Known constraints
- The `provider` in `schema.prisma` is already `postgresql` — do **not** change it.
- `DATABASE_URL` and `DIRECT_URL` can point to the same local Postgres instance/port for local dev (no PgBouncer needed). Remove the `?pgbouncer=true&connection_limit=1` query params.
- Do not commit real connection strings to `.env` — real values belong in `.env.local`.
- The `web/prisma/migrations/` folder already has the full schema in SQL; `prisma migrate deploy` (not `dev`) is used in production/build.

## Requirements

### Step 1 — Provision the local database in WebStorm
1. Open **WebStorm → Database** tool window (View → Tool Windows → Database).
2. Click **+** → **Data Source** → **PostgreSQL**.
3. Fill in:
   - **Host:** `localhost`
   - **Port:** `5432` (default; WebStorm will auto-select a free port if 5432 is taken — note the actual port)
   - **Database:** `moto_ai_dev`
   - **User:** `postgres` (or any user you create)
   - **Password:** choose a dev password
4. Click **Test Connection** — WebStorm will offer to download the JDBC driver if missing.
5. Click **OK** to save the data source.

### Step 2 — Update `.env.local` with local credentials
Replace (or create) the following entries in `web/.env.local`:

```dotenv
# Local PostgreSQL — WebStorm-managed dev instance
DATABASE_URL="postgresql://postgres:<password>@localhost:<port>/moto_ai_dev"
DIRECT_URL="postgresql://postgres:<password>@localhost:<port>/moto_ai_dev"
```

- Both URLs point to the same local server (no pooler needed in dev).
- No query params (`pgbouncer`, `connection_limit`) required.

### Step 3 — Neutralize the placeholder in `.env`
The `.env` file ships with placeholder Supabase URLs. Replace both values with empty strings so they do not accidentally override `.env.local`:

```dotenv
DATABASE_URL=""
DIRECT_URL=""
```

> Prisma loads `.env` first, then `.env.local` overrides — empty strings in `.env` ensure the local values win.

### Step 4 — Apply migrations
From `web/`:
```bash
npx prisma migrate deploy   # applies the existing migration to the local DB
npx prisma generate         # regenerates the Prisma client
```

Alternatively use the npm scripts:
```bash
npm run db:migrate   # prisma migrate deploy
npm run db:generate  # prisma generate
```

### Step 5 — Verify
1. Run `npm run dev` — the Next.js server should start with no Prisma connection errors.
2. Open **WebStorm → Database → moto_ai_dev** and confirm the 5 tables exist:
   - `Session`
   - `LessonProgress`
   - `HotspotVisit`
   - `GeneratedQuiz`
   - `QuizAttempt`
3. Hit any API route that touches the DB (e.g., `POST /api/progress`) and confirm a 200 response with no DB errors in the terminal.
