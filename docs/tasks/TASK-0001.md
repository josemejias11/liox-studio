# TASK-0001: Sanity CMS health check — verify live data, schema alignment, and query contracts

## Goal
Query the live Sanity dataset, confirm published courses exist, and verify that every GROQ projection field aligns with the Zod contracts in `src/lib/contracts/sanity.ts` and with the deployed schema in `src/sanity/schemaTypes/`.

## Context
The project uses Sanity as its CMS with GROQ queries (`src/sanity/lib/queries.ts`) that are validated at the boundary by Zod schemas (`src/lib/contracts/sanity.ts`). Recent work added `scrollStory`, `dragDrop`, `colorSwitcher`, and `splitScreen` lesson types, plus a per-chapter `scrollChapters` field. This check confirms the live dataset reflects the current schema and that no projection field has drifted out of sync with its Zod counterpart.

## Affected Area
- Layer: cross-cutting (CMS data → TypeScript contracts → React components)
- Agent role: qa-automation-engineer

// web/src/sanity/lib/queries.ts
export const COURSES_QUERY: string          // lists published courses

### Patterns in use
- All Sanity reads go through `readClient` (CDN, no token); studio mutations via `sanityClient`.
- Zod schemas use `opt()` helper to normalize `null → undefined`; every nullable GROQ projection uses `opt()` on the Zod side.
- `lessonType` enum in contracts must match the `lessonType` options list in `lessonType` schema: `content | interaction | stage | video | quiz | colorSwitcher | splitScreen | dragDrop | scrollStory`.
- `QUIZ_GRADING_QUERY` is server-only — its answer fields (`isCorrect`, `feedback`, `explanation`) deliberately absent from `QUIZ_FIELDS` / `quizDocSchema`.
- `COURSE_BY_SLUG_QUERY` filters `published == true`; unpublished courses never reach the frontend.

### Known constraints
- `QUIZ_GRADING_QUERY` must never be validated client-side — it contains answer keys.
- `chapterType.slug` must be present for navigation; missing slugs cause 404s.
- `lessonSchema.lessonType` uses `.catch('content')` — unrecognized types silently degrade to content; the check should catch this case.

## Requirements
1. Use the Sanity MCP (`mcp__Sanity__whoami`, `mcp__Sanity__query_documents`, `mcp__Sanity__get_schema`) to:
   a. Confirm which Sanity project and dataset are active.
   b. Run `COURSES_QUERY` against the live dataset and report how many courses are published.
   c. For each published course, run `COURSE_BY_SLUG_QUERY` and validate the result against `courseSchema` — report any Zod parse errors.
2. Compare every field projected in `LESSON_FIELDS`, `SPEC_FIELDS`, `QUIZ_FIELDS`, `DISCLAIMER_FIELDS`, and `CHAPTER_FIELDS` against the corresponding Zod schema — flag any field present in the GROQ projection but missing from Zod (or vice-versa).
3. Confirm the `lessonType` enum values in `lessonSchema` (in `contracts/sanity.ts`) exactly match the `options.list[].value` entries in `lessonType` schema (`schemaTypes/lesson.ts`).
4. Check whether any deployed lesson documents use a `lessonType` value not covered by the enum (would silently fall back to `content` via `.catch()`).
5. Confirm `QUIZ_GRADING_QUERY` fields (`isCorrect`, `feedback`, `explanation`) are absent from `QUIZ_FIELDS` and `quizDocSchema`.
6. Report a summary: ✅ / ❌ per check, with specific mismatches highlighted.
